# MTProto: самостоятельная установка на VPS

Эта инструкция поднимает отдельный Telegram MTProto-прокси на собственном VPS. MTProto проксирует трафик Telegram и не является системным VPN: браузер, другие приложения и общий трафик через него не пойдут.

Используется официальный исходный код [TelegramMessenger/MTProxy](https://github.com/TelegramMessenger/MTProxy). Публичный репозиторий не содержит реальных адресов, секретов, готовых ссылок или production-конфигурации.

## Важное ограничение по портам

Основной установщик этого репозитория уже занимает TCP/UDP 443 под VLESS + REALITY и Hysteria2. Поэтому MTProto нужно запускать на отдельном TCP-порту, например `2053`, либо на отдельном VPS. Не запускайте два сервиса на одном TCP-порту.

## Требования

- чистый Ubuntu 22.04/24.04 или Debian 12/13;
- root или пользователь с `sudo` без интерактивного пароля;
- внешний IPv4/IPv6-адрес или DNS-имя VPS;
- открытый TCP-порт `2053` в облачном firewall и на сервере;
- SSH-доступ с отдельной сессией для отката.

## Установка официального MTProxy

Команды ниже выполняются на VPS:

```bash
sudo apt update
sudo apt install -y git curl build-essential libssl-dev zlib1g-dev openssl xxd ufw
sudo groupadd --system mtproxy 2>/dev/null || true
sudo useradd --system --no-create-home --gid mtproxy --shell /usr/sbin/nologin mtproxy 2>/dev/null || true
id mtproxy
sudo install -d -o root -g mtproxy -m 0750 /etc/mtproxy
sudo install -d -o root -g root -m 0755 /opt

if [ -e /opt/MTProxy ]; then
  sudo mv /opt/MTProxy "/opt/MTProxy.backup.$(date -u +%Y%m%dT%H%M%SZ)"
fi
sudo git clone --depth 1 https://github.com/TelegramMessenger/MTProxy /opt/MTProxy
sudo make -C /opt/MTProxy
sudo test -x /opt/MTProxy/objs/bin/mtproto-proxy
```

Если сборка завершилась ошибкой после неполного запуска, повторите:

```bash
sudo make -C /opt/MTProxy clean
sudo make -C /opt/MTProxy
```

## Получение конфигурации Telegram

Официальный MTProxy использует `proxy-secret` и `proxy-multi.conf`. Загружайте их по HTTPS и устанавливайте с безопасными правами:

```bash
tmp_dir="$(mktemp -d)"
trap 'rm -rf "$tmp_dir"' EXIT

curl --fail --silent --show-error --location --proto '=https' --proto-redir '=https' --tlsv1.2 \
  https://core.telegram.org/getProxySecret -o "$tmp_dir/proxy-secret"
curl --fail --silent --show-error --location --proto '=https' --proto-redir '=https' --tlsv1.2 \
  https://core.telegram.org/getProxyConfig -o "$tmp_dir/proxy-multi.conf"

test -s "$tmp_dir/proxy-secret"
test "$(wc -c < "$tmp_dir/proxy-multi.conf")" -ge 64
grep -q '^default ' "$tmp_dir/proxy-multi.conf"
grep -q '^proxy_for ' "$tmp_dir/proxy-multi.conf"

sudo install -o root -g mtproxy -m 0640 "$tmp_dir/proxy-secret" /etc/mtproxy/proxy-secret
sudo install -o root -g mtproxy -m 0640 "$tmp_dir/proxy-multi.conf" /etc/mtproxy/proxy-multi.conf
sudo -u mtproxy test -r /etc/mtproxy/proxy-secret
sudo -u mtproxy test -r /etc/mtproxy/proxy-multi.conf
```

`proxy-multi.conf` рекомендуется обновлять примерно раз в сутки. Не публикуйте его содержимое и не добавляйте эти файлы в Git.

## Генерация пользовательского секрета

Секрет клиента — случайное 16-байтовое значение в hex-формате. Храните его защищённо и раскрывайте только в персональной ссылке:

```bash
user_secret="$(openssl rand -hex 16)"
printf 'MTPROXY_USER_SECRET=%s\n' "$user_secret" | \
  sudo tee /etc/mtproxy/mtproxy.env >/dev/null
sudo chown root:mtproxy /etc/mtproxy/mtproxy.env
sudo chmod 0640 /etc/mtproxy/mtproxy.env
unset user_secret
```

Для нескольких людей создавайте отдельный секрет на пользователя или устройство. Не отправляйте один секрет в общий чат.

## Systemd-сервис

В примере `2053` — публичный порт клиентов, а `8888` — локальный порт статистики. Процесс стартует с правами root, чтобы открыть порт, и снижает права до системного пользователя `mtproxy` через параметр `-u` официального MTProxy.

Создайте `/etc/systemd/system/mtproxy.service`:

```ini
[Unit]
Description=Telegram MTProto proxy
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
EnvironmentFile=/etc/mtproxy/mtproxy.env
WorkingDirectory=/opt/MTProxy/objs/bin
ExecStart=/opt/MTProxy/objs/bin/mtproto-proxy -u mtproxy -p 8888 -H 2053 -S ${MTPROXY_USER_SECRET} --aes-pwd /etc/mtproxy/proxy-secret /etc/mtproxy/proxy-multi.conf -M 1
Restart=on-failure
RestartSec=5s
UMask=0077
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

Запустите сервис:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now mtproxy.service
sudo systemctl is-active mtproxy.service
sudo ss -lntp | grep -E ':(2053|8888)\b'
```

## Firewall

Добавьте только порт клиентов. Правило SSH не меняйте, пока не проверите второй SSH-сеанс:

```bash
sudo ufw allow 2053/tcp
sudo ufw deny 8888/tcp
sudo ufw status verbose
```

В облачном firewall провайдера также разрешите `TCP 2053`. Не открывайте `8888`, `proxy-secret` или `mtproxy.env` наружу.

## Формирование ссылки

Ссылка Telegram имеет вид:

```text
tg://proxy?server=<адрес_VPS_или_DNS>&port=2053&secret=<секрет>
```

Для браузерного перехода можно использовать форму `https://t.me/proxy?server=<адрес>&port=2053&secret=<секрет>`. Подставляйте значения только на локальной машине или в личном чате Telegram.

```bash
public_host='proxy.example.com'
user_secret="$(sudo sed -n 's/^MTPROXY_USER_SECRET=//p' /etc/mtproxy/mtproxy.env)"
printf 'tg://proxy?server=%s&port=2053&secret=%s\n' "$public_host" "$user_secret"
unset public_host user_secret
```

После открытия ссылки Telegram предложит добавить прокси. Проверьте отправку и получение сообщения, открытие медиа и повторное подключение после перезапуска.

По желанию можно зарегистрировать прокси через официальный [@MTProxybot](https://t.me/MTProxybot) и получить тег статистики. Тег не заменяет пользовательский секрет и не должен храниться в публичном репозитории.

## Проверка после установки

```bash
sudo systemctl status mtproxy.service --no-pager --full
sudo journalctl -u mtproxy.service -n 100 --no-pager
sudo ss -lntp | grep ':2053\b'
sudo ss -lntp | grep ':8888\b'
curl --fail http://127.0.0.1:8888/stats
```

С другого устройства проверьте, что `TCP 2053` доступен, а `TCP 8888` недоступен. Затем подключите ссылку в Telegram и отправьте тестовое сообщение. HTTP 200, открытый TCP-порт или зелёный ping сами по себе не доказывают работу через прокси.

## Обновление `proxy-multi.conf`

Официальная документация рекомендует периодически обновлять конфигурацию Telegram:

```bash
tmp_config="$(mktemp)"
trap 'rm -f "$tmp_config"' EXIT
curl --fail --silent --show-error --location --proto '=https' --proto-redir '=https' --tlsv1.2 \
  https://core.telegram.org/getProxyConfig -o "$tmp_config"
test "$(wc -c < "$tmp_config")" -ge 64
grep -q '^default ' "$tmp_config"
grep -q '^proxy_for ' "$tmp_config"
sudo install -o root -g mtproxy -m 0640 "$tmp_config" /etc/mtproxy/proxy-multi.conf
sudo systemctl restart mtproxy.service
sudo systemctl is-active mtproxy.service
```

После перезапуска повторите физическую проверку в Telegram. Автоматический timer добавляйте только после успешной ручной проверки и с сохранением отката.

## Отзыв и перевыпуск

При утечке секрета сгенерируйте новый, замените значение в `/etc/mtproxy/mtproxy.env`, перезапустите сервис и выдайте новую ссылку:

```bash
sudo cp -p /etc/mtproxy/mtproxy.env "/etc/mtproxy/mtproxy.env.backup.$(date -u +%Y%m%dT%H%M%SZ)"
sudo sed -i "s/^MTPROXY_USER_SECRET=.*/MTPROXY_USER_SECRET=$(openssl rand -hex 16)/" /etc/mtproxy/mtproxy.env
sudo chmod 0640 /etc/mtproxy/mtproxy.env
sudo systemctl restart mtproxy.service
sudo systemctl is-active mtproxy.service
```

Старые ссылки после этого перестанут работать. Удалите резервный файл после проверки нового секрета.

## Диагностика

**Сервис не запускается**

```bash
sudo systemctl status mtproxy.service --no-pager --full
sudo journalctl -u mtproxy.service -b --no-pager
sudo test -x /opt/MTProxy/objs/bin/mtproto-proxy
sudo test -s /etc/mtproxy/proxy-secret
sudo test -s /etc/mtproxy/proxy-multi.conf
```

**`address already in use`**

Другой процесс занял TCP 2053 или TCP 443. Выберите свободный порт, измените `-H`, firewall и ссылку одновременно. Не останавливайте рабочий Xray/Hysteria2 вслепую.

**Ссылка добавляется, но Telegram не подключается**

Проверьте адрес, порт, секрет, облачный firewall, системные часы и физическую сеть клиента. Скопируйте ссылку заново из защищённого источника; не используйте старую ссылку после перевыпуска секрета.

## Безопасность и границы

- не коммитьте `mtproxy.env`, `proxy-secret`, `proxy-multi.conf`, QR-коды и `tg://`/`t.me` ссылки;
- не вставляйте секрет в issue, pull request, общий чат или URL мониторинга;
- для бота используйте только личную выдачу и привязку к Telegram ID/устройству;
- после утечки сразу перевыпустите секрет и проверьте журналы доступа;
- Fake-TLS, платный биллинг, балансировщик, цепочки прокси и production-бот сюда не входят: для них нужны отдельные проверяемые конфигурации и физический тест клиента.
