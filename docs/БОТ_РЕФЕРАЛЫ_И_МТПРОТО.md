# Реферальные ссылки и Telegram-прокси

Этот публичный комплект предназначен для самостоятельной установки на свой VPS. В нём нет общего Telegram-бота, платёжной базы или production-доступа ZHUCK VPN. Раздел ниже описывает безопасный контракт интеграции, если владелец добавляет собственного бота.

## Реферальная ссылка пользователя

Реферальную ссылку формируйте только после получения настоящего имени бота через `getMe`. Не храните имя бота в исходниках и не подставляйте его из сообщения пользователя.

Формат ссылки:

```text
https://t.me/<имя_бота>?start=ref_<telegram_id>
```

Правила:

1. Разрешайте в имени бота только `A-Z`, `a-z`, цифры и `_`.
2. В идентификаторе приглашавшего допускайте только целое число Telegram ID.
3. Не начисляйте бонус за собственный переход, повторную регистрацию или подмену параметра `start`.
4. Храните факт первого приглашения отдельно и обрабатывайте его идемпотентно.
5. Не публикуйте в репозитории таблицу пользователей, токены бота и платёжные данные.

## Персональная ссылка MTProto

Ссылка должна создаваться для конкретного Telegram ID и привязанного устройства. В ссылку нельзя включать открытый список пользователей или общий секрет.

Поддерживаемый Telegram формат:

```text
tg://proxy?server=<адрес>&port=<порт>&secret=<секрет>
```

Проверки перед выдачей:

- порт принадлежит назначенной строке пользователя, а не общему fallback-порту;
- секрет хранится только на сервере и в защищённой БД;
- срок доступа и статус устройства проверяются перед каждым показом ссылки;
- выдача происходит в личном чате, а не в группе;
- после перевыпуска старая ссылка отзывается или помечается истёкшей.

В Telegram используйте кнопку с URL, а не обычный текст ссылки:

```python
InlineKeyboardButton("🟢 Подключить в Telegram", url=link)
```

## Режим без платежей

Если выдача доступа закрыта, бот должен явно сообщить, что активного MTProto-доступа нет. Не показывайте кнопку покупки и не создавайте пустую ссылку.

## Проверка

Пинг не доказывает работу прокси. После выдачи проверьте:

1. установку прокси в Telegram;
2. отправку и получение сообщения;
3. повторное открытие ссылки после перезапуска приложения;
4. отзыв или истечение доступа;
5. отсутствие секрета и полного URL в журнале бота.

## Что не входит в публичный комплект

Публичный репозиторий намеренно не содержит внутренние файлы ZHUCK VPN, production-бота, реальные адреса узлов, ключи, UUID, токены, подписки и резервные копии. Для общего бота используйте отдельный закрытый репозиторий и секреты GitHub Actions/хостинга.
